# Security Policy

## Supported Versions

Only the latest release line receives security fixes.

| Version | Supported          |
| ------- | ------------------ |
| 2.x (CSIP-Aus v1.3)  | :white_check_mark: |
| 1.x (CSIP-Aus v1.2)  | :white_check_mark: |
| < 1.0   | :x: |

## Reporting a Vulnerability

**Please do not report security issues through public issues, pull requests, or discussions.**

Instead, report them privately via GitHub:
[Report a vulnerability](https://github.com/bsgip/envoy/security/advisories/new)

If you can't use GitHub, email support`at`bsgip.com

Please include:
- A description of the issue and its impact
- Steps to reproduce or a proof of concept
- Affected versions, if known
- Any suggested fix (welcome, but please share it privately)

## What to Expect

- **Acknowledgement** within 5 working days
- **Initial assessment** within 14 days
- We'll keep you updated as we work on a fix, and agree on a disclosure date with you
- Once fixed, we'll publish a GitHub Security Advisory (requesting a CVE where appropriate) and credit you, unless you'd prefer to remain anonymous

Timelines are best-effort.

## Scope

Out of scope:
- Vulnerabilities in dependencies that are already publicly known (please report those upstream)
- Issues that require an already-compromised machine or privileged access
- Missing hardening that isn't an exploitable issue
